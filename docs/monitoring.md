# Мониторинг бэкапов

На Pi работают node_exporter, Prometheus, Alertmanager и Grafana.
Скрипты атомарно обновляют `.prom`-файлы: результат каждого запуска отдельно
от времени последнего успеха. Поэтому ошибка не обнуляет возраст рабочего бэкапа.

Дашборд содержит 12 панелей: возраст бэкапа и проверки, результат последних
запусков, длительности, размер архива, число снимков и свободное место.
История результата отражает последнее состояние на момент scrape, а не каждый
запуск: короткий сбой между двумя scrape может не попасть на график.

На ноутбуке открой туннель:

```sh
ssh -N -L 13000:127.0.0.1:3000 rasp_ether
```

Затем открой http://localhost:13000/d/vaultwarden-backups . Просмотр без пароля;
доступ к порту на Pi возможен только локально или через SSH.

Шесть правил проверяют устаревшие бэкапы и восстановления, отсутствие метрик,
ошибки textfile collector, доступность node_exporter и свободное место.
Для возраста порог 26 часов, выдержка `for: 5m`, затем `group_wait: 30s`.

Проверено: свежие, устаревшие и отсутствующие метрики тестами `promtool`;
все 12 запросов дашборда возвращают данные через Grafana; три цели Prometheus
имеют состояние `up`. В живом тесте дополнительная метрика возраста 30 часов
дала `pending` через 52 с, `firing` через 350 с и успешную отправку Telegram
через 380 с. Тестовая метрика удалена, активных алертов после удаления нет.

Мониторинг работает на том же Pi, что и бэкапы. При отключении Pi или прокси
он сам не сможет сообщить об аварии. Внешний heartbeat остаётся отдельной задачей.

Установка и команды проверки: [monitoring/README.md](../monitoring/README.md).
